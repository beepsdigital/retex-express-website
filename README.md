# RetEx Express — website

Bilingual (English + Arabic) SEO-optimised static website for RetEx Express, a courier, cargo and logistics company in Al Aziziyah, Riyadh.

- Research and Google Business Profile analysis: `docs/research/gbp-analysis.md`
- Design spec: `docs/superpowers/specs/2026-10-04-retex-website-design.md`
- Implementation plan: `docs/superpowers/plans/2026-10-04-retex-website-plan.md`

## Requirements

Node.js 18 or newer. No npm packages are needed. The image pipeline (optional, only when the source artwork changes) needs Windows PowerShell.

## Commands

```bash
npm run build     # renders the site into dist/
npm test          # builds, then runs the SEO + link integrity checks
npm run serve     # previews dist/ at http://localhost:8080/
npm run images    # regenerates src/assets/img from source-assets/ (Windows only)
```

## Where things live

| Path | What it is |
|---|---|
| `site.config.js` | Business facts: domain, name, phone, WhatsApp, address, hours, Google Place ID, social links, analytics ID |
| `src/content/en.js` | Every English string, page, service, destination and FAQ |
| `src/content/ar.js` | The Arabic equivalent (same shape) |
| `src/templates/` | Page layout, components, page renderers, JSON-LD builders |
| `src/assets/css/main.css` | Design system and layout (RTL-aware) |
| `src/assets/js/main.js` | Mobile nav, quote form → WhatsApp, reveal animations |
| `src/assets/img/` | Processed images (generated by `tools/images.ps1`) |
| `src/static/` | robots-level files copied as-is: `_headers`, `.htaccess`, `manifest.webmanifest`, `favicon.svg` |
| `build.js` | Static site generator (also writes `sitemap.xml`, `robots.txt`, `llms.txt`) |
| `test.js` | Post-build checks: titles, descriptions, canonical, hreflang, one H1, links, images, JSON-LD, sitemap, EN/AR parity |
| `dist/` | Build output. Upload this folder to the host. |

## Editing content

Open `src/content/en.js` and `src/content/ar.js`. Each service and destination is one object with its `meta` (title + description), `h1`, `lead`, `sections`, related links and `faq`. Keep both files in step: the build fails if a slug exists in one language only.

To add a destination, copy one entry in the `destinations` array of **both** files, change `slug`, `code`, `name`, `cities`, `modes`, `schemaName`, the copy and the FAQs, then run `npm test`.

Links inside copy use `@@/path/` (for example `<a href="@@/services/air-cargo/">`) so they resolve correctly under `/` and `/ar/`.

## Demo hosting (GitHub Pages)

Every push to `main` runs `.github/workflows/deploy.yml`, which builds the site, runs the tests and publishes `dist/` to GitHub Pages. The build writes a `CNAME` file from `siteUrl`, so the Pages custom domain follows the config.

Current demo domain: **logistics-demo.beepsdigital.com**. For it to resolve, add this DNS record at the provider that hosts beepsdigital.com:

| Type | Name | Value |
|---|---|---|
| CNAME | `logistics-demo` | `<github-username>.github.io` |

Then in the repository go to Settings → Pages, confirm the custom domain shows as verified, and tick "Enforce HTTPS" once the certificate has been issued (usually within an hour of the DNS change). If beepsdigital.com is on Cloudflare, keep the record DNS-only (grey cloud) until HTTPS is enforced.

## Before launch

1. Set `siteUrl` in `site.config.js` to the real domain and rebuild.
2. Add the street address to `address.street` when the client confirms it (also add it to the Google Business Profile).
3. Add social profile URLs to `social` (they feed the schema `sameAs`) and, if wanted, a GA4 ID to `analytics.gtagId`.
4. Run `npm test` and fix anything it reports.
5. Deploy `dist/`:
   - Netlify / Cloudflare Pages / Vercel static: upload the folder; `_headers` is applied automatically on Netlify and Cloudflare Pages.
   - Apache / cPanel: upload the folder contents to `public_html`; `.htaccess` handles HTTPS, trailing slashes, caching and the 404 pages.
6. Add the live URL to the Google Business Profile, submit `https://<domain>/sitemap.xml` in Google Search Console, and run the Rich Results test on the home page, one service page and one destination page.

## Known limitations and items for the client to confirm

- **Domain, street address, namesake company, extra corridors** — see the assumptions table in the spec (§2). The site deliberately avoids prices, transit times and tracking promises until the client confirms them.
- **Photos** — every image is cropped from the one flyer supplied (1024px wide), so intro images are capped at 480px to avoid blur. Real photos of the shop, team, vehicles and packing (at least 1200px wide) will noticeably improve the pages and the Google listing.
- **Arabic copy** — written natively but should get a quick read-through by the client for house terminology (for example the words used for labelling and plus codes).
- **Analytics** — the privacy policy says the site sets no tracking cookies. If you set `analytics.gtagId`, update the privacy page accordingly.
- **Hosting notes** — `.htaccess` uses Apache 2.4 `<If>` blocks for the Arabic 404 page, and its HTTPS redirect can loop behind a CDN using flexible SSL (disable the redirect block there and let the CDN enforce HTTPS). The keyless Google Maps embed on the contact page is an undocumented endpoint; the "View on Google Maps" link beside it is the fallback.
- **Structured data** — the `streetAddress` currently carries the district plus the plus code until a street address exists.
