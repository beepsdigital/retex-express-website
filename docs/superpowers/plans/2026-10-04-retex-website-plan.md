# RetEx Express Website Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and verify a bilingual (English + Arabic), SEO-optimised static website for RetEx Express that deploys as plain files from `dist/`.

**Architecture:** A zero-dependency Node script renders JS template literals with per-language content objects into `dist/` (English at `/`, Arabic at `/ar/`). Structured data, hreflang, sitemap, robots and llms.txt are generated by the same build. A post-build test script checks SEO invariants and link integrity.

**Tech Stack:** Node.js 24 (no npm packages), HTML5, CSS (custom properties, logical properties for RTL), vanilla JS, Windows PowerShell + GDI+ for the image pipeline.

**Spec:** `docs/superpowers/specs/2026-10-04-retex-website-design.md`

## Global Constraints

- Node ≥ 18; `npm run build` must finish with zero dependencies installed.
- Brand name in copy: "RetEx Express"; listing name "RETEX Express Shipping" only in `legalName`/`alternateName`.
- NAP string must match the GBP exactly: phone `+966 55 873 6359`, district `Al Aziziyah`, city `Riyadh`, postal code `14512`, plus code `HPXX+QCV`.
- Hours: Sat–Thu 08:30–23:00, Fri 16:00–21:30.
- No prices and no transit-time promises in copy (spec A5).
- Titles 35–65 chars, descriptions 80–160 chars, exactly one `<h1>` per page.
- Every page: canonical + hreflang `en`, `ar`, `x-default`; `lang` and `dir` set.
- `siteUrl` is read from `site.config.js` only (placeholder `https://retexexpress.com`).
- Arabic pages use `dir="rtl"` and the Cairo font; English uses Plus Jakarta Sans.

## Review Focus

1. A page slug present in `en.js` but missing in `ar.js` (or vice versa) must fail the build with the slug named, not render a half-site. (Task 6 test `parity`.)
2. Arabic text containing `&`, `<` or quotes inside copy must be HTML-escaped only where it is inserted as text, never double-escaped in `<title>`/meta attributes. (Task 3 test `escape`.)
3. A visitor with JavaScript disabled must still be able to reach WhatsApp and call from the quote page. (Task 4: quote page renders static `wa.me`/`tel:` links outside the form.)
4. A content entry that references an image that does not exist in `src/assets/img` must fail the build. (Task 6 test `images`.)
5. The 404 page must not carry a canonical to itself and must be `noindex`. (Task 6 test `noindex`.)
